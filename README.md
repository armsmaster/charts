# Свечные графики MOEX

Приложение для аналитиков и SMM: строит свечные графики по данным Московской
Биржи (или по импортированному CSV), позволяет настроить оформление, сохранить
настройки в JSON и скачать готовый PNG.

```
┌──────────────┐        ┌────────────────────────────────────────┐
│  web (nginx) │  /api  │  api (FastAPI)                         │
│  статика +   ├───────►│  MOEX ISS loader · CSV parser ·        │
│  proxy       │        │  Plotly figure builder · PNG export    │
└──────────────┘        └──────────────────┬─────────────────────┘
   :8080                                    │ https
                                            ▼
                                   iss.moex.com/iss
```

## Быстрый старт

```bash
cp .env.example .env      # и поправить под целевую машину
docker compose build
docker compose up -d
```

* UI — <http://localhost:8080>
* Swagger — <http://localhost:8080/api/docs>

Проверить, что ISS доступна из контейнера:

```bash
docker compose exec api python -m moexcharts.smoke SBER
```

## Развёртывание за корпоративным периметром

Всё, что отличается на рабочем ПК, задаётся в `.env` — код менять не нужно.

### Nexus вместо Docker Hub и PyPI

```dotenv
PYTHON_IMAGE=nexus.corp:8083/python:3.12-slim
NGINX_IMAGE=nexus.corp:8083/nginx:1.27-alpine
PIP_INDEX_URL=https://nexus.corp/repository/pypi-proxy/simple
PIP_TRUSTED_HOST=nexus.corp
APT_MIRROR=http://nexus.corp/repository/debian-proxy
```

`PIP_INDEX_URL` записывается в `/etc/pip.conf` на этапе сборки. `APT_MIRROR`
нужен только ради `libnss3` — библиотеки, которую использует Kaleido для
серверного рендеринга PNG. Если apt недоступен, сборка не падает: PNG будет
рендериться в браузере (см. «Экспорт PNG»).

Плагин `plotly.js` **не** тянется из CDN: он отдаётся из установленного пакета
`plotly` через `/api/vendor/plotly.min.js`. Никаких npm и внешних сетей для
фронтенда не требуется.

Русская локаль оси времени — единственный вендоренный вручную файл
(`api/src/moexcharts/assets/plotly-locale-ru.js`, ~1 КБ): в пакете `plotly`
её нет, а хост без CDN. Браузер грузит её из `/api/vendor/plotly-locale-ru.js`
и передаёт `{locale: "ru"}` в `Plotly.newPlot`; для серверного PNG та же
локаль вклеивается в бандл, которым питается Kaleido.

### Доступ к iss.moex.com без проверки SSL

```dotenv
CHARTS_MOEX_VERIFY_SSL=false
```

Проверка сертификата отключается **только** для запросов к ISS; при старте в
лог пишется предупреждение. Более аккуратный вариант — оставить проверку и
подложить корпоративный корневой сертификат: положить PEM в
`./certs/corp-root-ca.pem`, раскомментировать блок `volumes:` у сервиса `api` в
`docker-compose.yml` и указать `CHARTS_MOEX_CA_BUNDLE=/etc/ssl/corp-ca.crt`.

Если нужен исходящий прокси — `HTTPS_PROXY` / `HTTP_PROXY` / `NO_PROXY` в
`.env` передаются в контейнер и подхватываются httpx автоматически.

## Как этим пользоваться

1. **Инструмент.** Начните вводить тикер — подсказки приходят из
   `/iss/securities.json`. Тикер считается принятым, только когда ISS его
   подтвердила (`/iss/securities/{secid}.json`); режим торгов подбирается
   автоматически, но его можно задать вручную.
2. **Период и таймфрейм.** Список таймфреймов приходит с
   `iss.moex.com` (`/iss/index.json`, блок `durations`) — он не захардкожен.
   Заведомо неподъёмные сочетания («1 минута» за 5 лет) отклоняются с
   подсказкой до обращения к бирже.
3. **Оформление.** 98 настроек в 11 разделах: холст, шрифт, свечи, заголовок,
   подпись, обе оси, пропуски нерабочего времени, панель объёма, водяной знак.
   График перерисовывается на лету. У каждого цвета — пипетка **и** поле для
   ввода: hex можно вставить из буфера в любом виде (`#b9faf8`, `b9faf8`,
   `#f0a`), а также написать `rgba(255,0,0,.5)` или имя цвета. Некорректное
   значение подсвечивается и не применяется, пока не станет валидным.
4. **Пресеты.** «Сохранить пресет» скачивает JSON с оформлением, периодом и
   таймфреймом; «Загрузить пресет» возвращает всё обратно. Загруженный логотип
   хранится внутри файла, поэтому пресет самодостаточен — его можно просто
   переслать коллеге.
5. **Заголовок.** Отдельная карточка вверху панели — это то, что правят на
   каждом графике, поэтому оно не спрятано в аккордеон.
   * **Авто** — заголовок собирается по шаблону, по умолчанию
     `<b>{ticker}</b> | {candles}` → **SBER** | дневные свечи. Подстановки
     вставляются кликом по «фишке» (при клике в конец строки добавляется и
     разделитель `|`); наведение на фишку показывает, во что она развернётся
     для текущих данных. Части, которые развернулись в пустоту, и лишние `|`
     убираются автоматически.
   * **Свой текст** — литеральный заголовок. При первом переключении поле
     заполняется текущим авто-заголовком, чтобы было от чего оттолкнуться.
   * Кнопки **Ж** / **К** оборачивают выделение в `<b>` / `<i>`, **↵**
     вставляет перенос строки, **T** убирает все теги.
   * Ниже — предпросмотр ровно в том виде, в каком заголовок попадёт на
     график: разметку рендерит тот же серверный шаблонизатор.
   * Размер, цвет и положение заголовка остались в разделе «Заголовок»
     аккордеона — это оформление, а не текст.
6. **CSV.** Обязательные колонки — `open`, `high`, `low`, `close`, `begin`
   (лишние игнорируются). Таймфрейм в этом режиме не выбирается, а
   определяется по шагу между свечами; период по-прежнему доступен и
   отсчитывается **от последней свечи в файле**, а не от сегодняшнего дня.
   Парсер терпим к BOM, разделителям `,` `;` `tab`, десятичной запятой,
   кодировке cp1251, произвольному порядку колонок и обратной сортировке.

### Экспорт PNG

Кнопка «Скачать PNG» использует серверный рендеринг через Kaleido — он даёт
файл, гарантированно совпадающий с тем, что нарисовал бы сервер по API. Если
Kaleido в контейнере недоступен, `/api/meta/capabilities` сообщает об этом, и
UI сам переключается на рендеринг в браузере. Размер и множитель задаются в
разделе «Холст» (1200×900 ×2 по умолчанию).

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/meta/intervals` | таймфреймы из ISS |
| GET | `/api/meta/periods?source=` | пресеты периодов |
| GET | `/api/meta/style-schema` | описание всех настроек оформления для UI |
| GET | `/api/meta/title-placeholders` | подстановки для редактора заголовка |
| GET | `/api/meta/style-defaults` | значения по умолчанию |
| GET | `/api/meta/capabilities` | доступен ли серверный PNG, лимиты, колонки CSV |
| GET | `/api/instruments/search?q=` | поиск инструмента |
| GET | `/api/instruments/{secid}` | **валидация**: 404 — такого инструмента нет |
| GET | `/api/instruments/{secid}/boards` | режимы торгов |
| GET | `/api/series/moex?secid=&interval=&period=` | свечи из ISS |
| POST | `/api/series/csv` | свечи из загруженного файла |
| POST | `/api/charts/figure` | спецификация Plotly |
| POST | `/api/charts/png` | готовый PNG |
| POST | `/api/charts/title` | предложенный заголовок |
| POST | `/api/charts/watermark` | загрузка логотипа → data URI |

## Устройство кода

```
api/src/moexcharts/
  domain/      модели, периоды, порты (Protocol) — не знают ни про HTTP, ни про Plotly
  moex/        адаптер ISS: транспорт, справочник инструментов, загрузка свечей
  csvsource/   парсер CSV
  charting/    настройки оформления, построение фигуры, заголовки, PNG, водяной знак
  services.py  сценарии: «свечи из ISS», «свечи из файла»
  web/         FastAPI: схемы, роуты, обработка ошибок, сборка зависимостей
```

Направление зависимостей — только внутрь, к `domain`. Роуты типизированы
портами (`CandleSource`, `InstrumentDirectory`, `IntervalCatalog`,
`ImageRenderer`), а конкретные реализации собираются в одном месте —
`web/deps.py`. Поэтому тесты гоняют настоящее приложение против поддельной
ISS, а замена биржи или движка рендеринга не затрагивает HTTP-слой.

Два момента, которые стоит знать при доработке:

* **Оформление описано один раз** — в `charting/style.py`. Оттуда же
  генерируется схема формы для браузера, поэтому новое поле достаточно
  добавить в модель: в UI оно появится само, а в пресете сохранится
  автоматически. Флаг `hidden=True` убирает поле из общей формы, оставляя его
  в модели и в пресетах, — так текст заголовка отдан отдельному редактору и не
  дублируется в аккордеоне.
* **Фигура строится только на сервере.** Браузер получает готовую
  спецификацию Plotly и для превью, и для экспорта; Kaleido получает ту же
  самую. Второй реализации внешнего вида графика не существует.
